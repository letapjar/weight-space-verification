**Observations**

*Input channels.* The useful thing about W1 is that inputs that are always 0 never receive a gradient, so they keep their initial weights of roughly ±0.05–0.15. Large weights therefore show where each channel is actually active.

- **Channel 0 (agent) is active only in row 8.** In rows 1–7 every agent weight is initialisation-sized. For example, input 260 (row 5, column 2) is `0.018 0.012 0.029 0.000 0.008 …`. In row 8 the weights are large and vary smoothly with column. For units 1 and 3:
  - Cell (8,2): `0.657`, `0.409`
  - Cell (8,3): `0.503`, `0.442`
  - Cell (8,6): `-0.334`, `-0.293`
  - Cell (8,7): `-0.565`, `-0.782`
  
  For unit 2, cell (8,8) is `-0.700`. This is a left-versus-right position code: the agent sits in the bottom row and its column changes.
- **Channel 1 (moving objects) is active only in rows 1–7.** Weights are large there, for example input 391 (7,8) `-2.019 1.168 1.053 1.326`, input 311 (6,2) `1.410`, input 256 (5,1) `1.155`, input 61 (1,2) `0.538`. In row 8 they are tiny, for example input 406 `0.027 …` and input 411 `-0.028 …`. So a moving object travels through the whole field above the agent but is never seen in the agent's row.
- **Channel 4 (previous frame) is large wherever channel 0 or channel 1 is active.** Examples: input 314 `1.533`, input 344 `-2.213`, input 174 `1.837`. It often has the opposite sign to channel 1 in the same cell, for example (2,2): channel 1 `0.510` against channel 4 `-0.529`. That is a motion detector, so the object's direction of travel matters and it is not simply falling.
- **Channel 2 (reward targets) is large only in rows 1–3.** Examples: (1,3) `0.321 … 0.470`, (1,5) `0.555`, (3,3) `-0.751`, (2,5) `0.294 … 0.566`. From row 4 down the weights are initialisation-sized, for example (4,2) `0.141 -0.056`. So the rewards are static targets in a block at the top.
- **Channel 3 (obstacles) is near initialisation everywhere inside the grid.** There are no obstacles inside the field, only the wall.

*Output layer.* For every hidden unit, the no-op, left and right columns of W3 are almost identical. Examples: row 27 is `0.128 | 0.172 0.160`, and row 87 is `-0.139 | -0.165 -0.154`. Only the up and down columns carry structure, with values such as `1.023`, `0.922`, `-0.985` for up and `1.004`, `-0.977`, `0.858` for down. The biases are `0.225 -0.292 -0.295 0.113 0.142`, which favour the no-op group.

So the policy is a three-way choice: one movement direction (up), the other (down), or stay (no-op, left and right together).

I linearised hidden unit 1, the unit for "agent is on the left side," through W2 and W3 over the first 67 layer-2 units. The partial sum is about −0.7 toward up minus down, so it pushes the logits toward **down**. In other words, when the agent is on the left, the policy favours down. Up and down appear to act as the two directions along the agent's single movement axis.

**Reasoning**

The inputs show:
- a controllable object confined to the bottom row whose column changes;
- one object moving with a direction that matters, anywhere above it but never in its row;
- static reward targets filling the top three rows;
- no interior obstacles.

That is the layout of Breakout: paddle, ball, bricks.

Other games fit worse:
- **Catch or fruit-falling games:** the reward objects would themselves move through every row, but channel 2 is only active in rows 1–3.
- **Pong:** the paddle would be a vertical bar in a side column moving through rows.
- **Frogger or Snake:** the agent would appear in many rows.
- **Maze or gridworld games:** there would be interior obstacles and a free-moving agent.
- **Space Invaders:** possible in principle, but the static top block plus a bouncing projectile whose motion matters fits Breakout better. Also, no action in this set means "fire."

The output layer conflicts with the labelled action meanings. Left and right are never told apart, while up and down are strongly separated. Given that, and that hidden unit 1 (agent on the left) pushes toward down, the most consistent reading is that in the training environment actions 1 and 2 shifted the paddle along its row. The left and right actions did nothing in practice and were lumped with no-op. This mismatch is the main source of my uncertainty.

**Played:** A Breakout-style brick-breaking game, similar to Atari Breakout or Arkanoid. A paddle in the bottom row keeps a bouncing ball in play so it can knock out a block of bricks in the top three rows. The paddle appears to be steered with actions 1 and 2 rather than left and right.

**Description:** The agent slides a paddle along the bottom row to intercept and return a bouncing ball. Reward comes from the ball hitting and removing the reward-target bricks in rows 1–3, and missing the ball ends play.
