**Observations**

*Input layout*
- Each input row's weights repeat with period 5: rows 115, 120, 125, 130, 165, 175, 215, 265, 270, 325 and others all show nearly the same pattern, roughly `+0.4 +1.2 −1.3 −1.2 −0.5 +0.6 −1.8 −1.7` (row 115: `0.428 1.228 −1.310 −1.203 −0.571 0.340 −1.861 −1.669`; row 270: `0.800 1.006 −1.149 −0.947 −0.239 0.897 −1.678 −1.727`).
- So the input is 100 cells × 5 features, stored cell by cell: index = 5·cell + channel.
- The cells form a 10×10 grid:
  - Inputs 0–104 and 430–499 (grid rows 0, 1 and 9, plus most of row 8) look like untrained initial values (|w| < 0.2).
  - Cells in columns 9 and 0 are quiet in every row: rows 145–154, 195–204, 245–254, 295–304, 345–354, 395–404.
  - The live area is grid rows 2–8, columns 1–8. This looks like a 10×10×C grid flattened as (row, col, channel), as MinAtar does.
- Channels 2 and 3 are quiet almost everywhere (e.g. rows 107/108, 117/118, 122/123). Only channels 0, 1 and 4 carry information.

*Channel 0*
- It is active only in a compact central blob: rows 2–8, columns about 2–7, centred near (5, 4.5).
- Most blob cells share the common pattern above, so it behaves like the position of a single roaming object.
- A few cells have large, distinctive weights, for example:
  - (3,4), row 170: `1.076 1.637 −2.354 … 1.263`
  - (4,5), row 225: `… 2.865 −2.577 …`
  - (6,3), row 315: `… −3.398`
  - (6,4), row 320: `−3.335 … −2.579 …`

*Channels 1 and 4*
- These are object channels spread over rows 2–7, columns 1–8, with position-specific detectors.
- Any object in grid row 2 drives h5 strongly: rows 106 `1.349`, 109 `1.305`, 121 `1.164`, 139 `1.491`, 144 `1.364`.
- Cells exactly 4 columns apart have nearly identical weights:
  - 311 / 331: `1.636 / 1.673`
  - 266 / 286: `1.067 / 0.994`
  - 161 / 181: `−0.971 / −0.962`
  - 169 / 189: `0.821 / 1.116`
  - 256 / 276: `−0.966 / −0.922`
  - 321 / 341: `−0.838 / −0.793`
  - 359 / 379: `0.853 / 0.774`
- That points to a data symmetry: objects arranged or moving periodically along rows.

*Outputs*
- The output columns are anti-correlated, not sharing a common component.
- Outputs 1 and 3 are strongly opposed: W3 rows `−0.003 0.263 −0.006 −0.803`, `−0.100 0.249 0.073 −0.876`, `0.152 −0.236 −0.191 0.669`.
- Outputs 2 and 4 tend to be opposed: `−0.065 −0.083 −0.295 0.351 0.301`, `0.011 −0.083 −0.202 0.017 0.292`.
- Outputs 0 and 2 move together: `0.368 −0.257 0.207`, `0.408 −0.261 0.188`, `0.443 −0.257 0.429`.
- This is the signature of 5 competing logits: no-op plus two pairs of opposite moves.

**Reasoning**

- A sequence or time-series input is ruled out by the 10-periodic dead columns.
- Plain counting or classification by channel is unlikely: two of the five channels are unused, and the weights are strongly position-specific.
- Q-values are unlikely, because DQN outputs share a large common state-value component and would be positively correlated. Here the columns compete like softmax logits.
- Two pairs of mutually opposed outputs plus one extra output fits a discrete action set: no-op, left, up, right, down. That is MinAtar's minimal Asterix action order `n, l, u, r, d`.
- The layout also fits a MinAtar-style game:
  - a 10×10 grid with a channel stack, flattened cell by cell;
  - one "player" channel (0) confined to a central roaming region;
  - object channels (1, 4) whose positions matter relative to that region;
  - unused channels (2, 3).
- The behaviour is plausible for a dodging game. For example, objects in the top row (2) push toward "left" and away from "no-op/up" via h5.
- The exact game is uncertain:
  - Standard MinAtar Asterix has 4 channels, so this would be a 5-channel variant or a similar custom grid game.
  - It could also be behaviour cloning of an expert in such a game.

**Task:** A policy (actor or behaviour-cloning) network for a 10×10, 5-channel grid game, mapping a one-hot object-map observation to logits over 5 discrete actions (no-op, left, up, right, down). It resembles a MinAtar Asterix-style dodge/collect agent.

**Description:** The network reads where the player (channel 0) and other objects (channels 1 and 4) are on a 10×10 board, compresses this into 8 features, and outputs scores for staying still or moving in each of the four directions.
